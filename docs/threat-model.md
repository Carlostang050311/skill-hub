# skill-hub 威胁模型

## 目标和信任边界

skill-hub 是本地优先工具，但它处理的内容可能来自 GitHub、插件缓存、用户下载目录和其他 Agent 客户端。默认假设：

- 本机用户是最终操作者；
- Skill 文本和资源不是天然可信；
- Web、CLI、MCP 可能同时运行；
- `SKILLHUB_HOME` 可以指向隔离测试库；
- 本地服务不应因为监听地址错误而暴露到局域网。

关键边界：

```text
远程仓库 / 插件缓存
        ↓ 解析、扫描、来源审查
本地库存与索引
        ↓ 用户确认 / 信任策略
评测 worker、安装、覆盖、恢复
        ↓
本机文件系统、网络、进程和凭据
```

## 需要保护的资产

- 用户的 Skill 正文、脚本、资源和本地配置；
- `origins`、库存、评测和备份历史；
- Provider API key、环境变量和本机凭据；
- 安装目标目录和用户自定义文件；
- 质量报告、公开榜单和可复现评测证据。

## 主要威胁与控制

| 威胁 | 现状 | 必须的控制 |
| --- | --- | --- |
| 恶意 Skill 读取本机文件或启动进程 | 执行评测没有 OS 隔离 | trusted-only、worker、网络和资源限制、审计 |
| 产物路径通过符号链接或竞态越界 | 当前有 realpath/lstat 检查，但存在 TOCTOU 窗口 | 打开文件句柄后校验、目录句柄/原子快照、拒绝链接 |
| 远程仓库超大文件耗尽资源 | clone/scan 无总量配额 | 文件数、单文件、总字节、超时和磁盘配额 |
| GitHub 更新替换用户修改 | 来源按名称覆盖，更新前风险信息不足 | revision、差异、权限变化、重新评测和 expected digest |
| Web/CLI 并发写坏状态 | JSON 直写、无统一锁 | Repository、schema version、临时文件 rename、进程锁 |
| 数据库文件锁泄漏 | 部分调用未 close | storage 层统一生命周期和 finally |
| 自定义 home 与真实 home 混写 | CLI GitHub 路径未贯穿 home | 所有状态路径由同一 HomeContext 派生 |
| 恶意 YAML 或正文注入评审 | 解析和评审边界不统一 | 统一 parser、输入长度限制、结构化诊断、提示词分隔 |
| 旧结果冒充当前质量 | 已有 hash 绑定，但结果模型仍较粗 | snapshot/scenario/prompt/rubric/evaluator 全绑定 |

## Trust level

| 等级 | 来源示例 | 允许行为 |
| --- | --- | --- |
| `unknown` | 新下载、未审查插件 | 可扫描、可查看；执行需一次性确认 |
| `reviewed` | 用户看过差异并确认来源 | 可在受限 worker 中执行 |
| `trusted` | 固定 revision、通过评测和人工审查 | 可自动纳入本地评测队列 |
| `blocked` | 恶意、解析异常或用户拉黑 | 禁止执行、安装和自动更新 |

## 安全验收标准

在声称“执行级评测安全”之前，至少要有：

1. 受限 worker 不能读写沙箱外路径。
2. 默认网络关闭，白名单可审计。
3. 子进程、CPU、内存、时间和磁盘有可验证上限。
4. 任何安装、覆盖、恢复和删除都有 expected digest 和可恢复记录。
5. 损坏状态文件不会静默清空或覆盖正常历史。
6. 本地 Web 只监听 loopback，并拒绝伪造 Host/Origin。

当前实现只满足第 6 项和部分路径校验；执行级评测仍属于受信任模式，不能标记为安全沙箱。
